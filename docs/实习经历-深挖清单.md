## 三条主攻故事（每条要能接住 3 轮追问）

### 1. 批量上传组件（最难也最值）

故事骨架：
> 乐器站后台要支持一次选多张图/视频上传。全并发发会导致服务器和浏览器压力大、失败难管；逐个排队又慢。我做了批量上传组件：文件先进队列，用 asyncPool 控制同时最多 N 个在传，每个文件有独立状态（待传/上传中/成功/失败），整体进度条，单个失败不中断其余。

asyncPool 核心代码（要能默写 + 讲清）：

```js
async function asyncPool(limit, items, fn) {
  const results = []   // 所有任务的 promise
  const running = []   // 正在执行的任务
  for (const item of items) {
    const p = Promise.resolve().then(() => fn(item))
    results.push(p)
    if (limit <= items.length) {
      const runner = p.then(() => running.splice(running.indexOf(runner), 1))
      running.push(runner)
      if (running.length >= limit) {
        await Promise.race(running)   // 等任意一个完成，腾出名额
      }
    }
  }
  return Promise.all(results)
}
```

追问链：
- 为什么不能全并发？（压力大、失败难管）
- 为什么用 Promise.race？（谁先完成谁腾名额，等一个就够）
- 进度条怎么算？（成功数/总数，或按字节）
- 单个失败怎么办？（try/catch 标记失败不中断，可重试）
- 前端校验和后端校验为什么都要？（防手滑 vs 防绕过）
- multer 怎么接批量？（upload.array('files', n)）
- 中转 vs OSS 直传？（中转简单但占服务器带宽；直传要 STS，大文件才用）

## 追问答案（Q&A 完整版）

### 批量上传（6 问）

1. 介绍一下组件？→ 后台要一次选多张图/视频上传。全并发压力大、失败难管，逐个排又慢。做了批量上传组件：文件进队列，asyncPool 控制同时最多 N 个在传，每个文件独立状态，整体进度条，单点失败不中断。
2. 为什么不能全并发？→ 同时几十个请求，浏览器和服务器压力大，失败和状态难管理。并发控制在吞吐和稳定之间取平衡。
3. asyncPool 怎么实现？为什么 Promise.race？→ running 存正在执行的，池满时 await Promise.race(running)，任意一个完成就腾名额继续。race 是"谁先完成算谁"，我们只需要一个名额。
4. 单个失败怎么办？→ 上传函数内部 try/catch，失败只标记状态不抛错，race 不被炸，其余继续，最后数成功/失败驱动进度条和重试。
5. 前端校验和后端校验为什么都要？→ 前端防手滑省流量，后端防绕过——接口公开，不能只信前端。
6. 大文件怎么办？→ 了解两种架构：服务端中转（简单但占带宽）和前端直传 OSS（STS + 分片，大文件快）。当前用中转够用。

### OSS 排查（5 问）

1. 介绍一下？→ 线上上传全挂。控制变量、分层排除：换页面/浏览器排除前端 → ?x=1 绕过 CDN 排除缓存 → OSS 原始域名直连排除网关 → 拿到 UserDisable，欠费冻结，推动运维充值恢复。
2. 为什么 ?x=1 能绕过 CDN？→ CDN 缓存 key 默认不看 query，加不同参数当新 URL，强制回源拿真实响应（缓存穿透测试）。
3. 为什么这个顺序？→ 从最接近用户的层开始，每层只改变一个变量，问题范围逐层缩小。
4. UserDisable 是什么？→ OSS 欠费被冻结，所有请求被拒，账号级问题，充值解冻。
5. 最大收获？→ 线上问题第一反应不是猜，是换变量 + 分层排除，可复用到任何故障。

### 视频优化（5 问）

1. 介绍一下？→ 主视频 28.5MB 首帧慢。解析 MP4 发现 moov 在文件末尾，要整包下载才能播。ffmpeg 重编码（H.264 + CRF 23 + faststart）moov 前置，压到 6.78MB（-76%），边下边播。
2. moov 和 mdat？→ MP4 box 结构：moov 元数据（时长/分辨率/关键帧索引），mdat 媒体数据，播放器先读 moov 才知道怎么解码。
3. 为什么 moov 在末尾就慢？→ 要下完整个 mdat 才能拿到 moov。faststart 挪到头部，先拿元数据边下边播。
4. ffmpeg 命令 / CRF？→ ffmpeg -i in.mp4 -c:v libx264 -crf 23 -movflags +faststart out.mp4。CRF 恒定质量，越小越清晰越大，23 默认；H.264 兼容最好（HEVC 不被 Chrome/Firefox 支持）。
5. 怎么验证流式？→ Range: bytes=0- 请求返回 206 Partial Content，证明分段传输；配合 Cache-Control 7 天。
